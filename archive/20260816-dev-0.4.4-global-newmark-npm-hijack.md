# dev-0.4.4 全局 Newmark 命令被 npm 0.2.1 劫持（实机"没任何变动"的真正原因，2026-08-16）

## 现象

用户多轮实机测试安装版 0.4.4 后报告 TUI 光标追踪"没任何变动"，滚轮仍能滚回旧帧。

## 根因

全局 `Newmark --TUI` 实际解析到的是 **npm 全局包 `newmark-agent@0.2.1`** 的 shim（`C:\Users\12252\AppData\Roaming\npm\newmark.cmd`），而非 `C:\Program Files\Newmark Agent\Newmark.exe`（0.4.4）。`AppData\Roaming\npm` 在 PATH 中排在 Program Files 之前，`where.exe Newmark` 顺序为：

1. `C:\Users\12252\AppData\Roaming\npm\newmark`（0.2.1 shim）
2. `C:\Users\12252\AppData\Roaming\npm\newmark.cmd`
3. `C:\Program Files\Newmark Agent\Newmark.bat`
4. `C:\Program Files\Newmark Agent\Newmark.exe`

因此此前所有 TUI 修复（居中滚动、严格窗口约束、备用屏、VT 启用）都落在 0.4.4 里，而用户始终在跑 0.2.1 的旧 TUI——"没任何变动"。

## 处理

1. `npm uninstall -g newmark-agent`（移除 158 个包）。
2. 验证：`Get-Command Newmark` → `C:\Program Files\Newmark Agent\Newmark.exe`；`where.exe Newmark` 只剩 Program Files 的 .bat/.exe。
3. node-pty 全链路（`Newmark.exe --TUI --demo` + `NEWMARK_TUI_DEMO_MODELS=60`）复验：`?1049h` 发出、model 视图导航正常、选中高亮 row 13 可见（`● Auto Newmark router`）、背景色 238 渲染正常。

## 结论

TUI 光标追踪的代码修复（备用屏 + Windows VT 处理启用）本身正确，此前未生效纯属命令解析指向旧版本。用户需在新终端重新 `where Newmark` 确认解析到 Program Files 0.4.4 后再实测。

## 备注

- 若以后再次出现"改代码没任何效果"，第一优先检查 `where <命令>` 的真实解析路径，而非继续改源码。
- npm 全局 0.2.1 的来源未追溯（早期误装），卸载即可；Program Files 0.4.4 不受影响。
