# dev-0.5.2 Android Agent terminal and calendar bridge

Date: 2026-08-21 (Asia/Shanghai)

## Acceptance scope

- Expose the existing sandboxed mobile terminal command engine to the local Build Agent.
- Keep Plan mode read-only and preserve all existing workspace path boundaries.
- Make calendar creation visibly request write permission before opening the default calendar app.
- Add a read tool for permission-authorized system calendar instances.
- Return explicit tool errors on permission denial, missing calendar app, provider rejection or invalid time ranges.

## Implementation boundary

`terminal_exec` takes one command string and calls `LocalToolExecutor.execute`. The executor instance remains alive for the complete Agent loop, so `cd` affects subsequent terminal calls in the same run. No process spawning or Android shell access was added.

Calendar calls are intercepted by the conversation runtime before the application-context fallback. The Activity uses `RequestPermission`, serializes concurrent requests with a coroutine `Mutex`, and holds the tool result until the permission callback completes. `calendar_create` requests `WRITE_CALENDAR` and launches `ACTION_INSERT` against `CalendarContract.Events.CONTENT_URI`. `calendar_read` requests `READ_CALENDAR` and queries `CalendarContract.Instances.CONTENT_URI`; defaults are now through 30 days, maximum output is 200 events, and optional title/location/description filtering occurs before projection.
