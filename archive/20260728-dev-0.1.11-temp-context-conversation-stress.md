# dev-0.1.11 Temporary-Root Context and Conversation Stress

Date: 2026-07-28

## Scope

Stress the packaged `dev-0.1.11` Windows renderer and real IPC path for rapid conversation creation/archive, then exercise the new bounded Memory Policy and the existing long-context compression pipeline under unique system temporary roots. No test used or modified the normal `~/.Newmark` runtime root.

The repeatable packaged gate is:

```powershell
cd DESKTOP
npm.cmd run test:temp-context-conversation-stress
```

Its scale can be controlled with `NEWMARK_STRESS_CONVERSATIONS`, `NEWMARK_STRESS_CLICK_INTERVAL_MS`, `NEWMARK_STRESS_COMPONENTS`, and `NEWMARK_STRESS_QUERIES`.

## Memory Policy results

A clean temporary Memory Lab was populated with 300 components: ten relevant adaptive-context memories and 290 content-sized distractors. Thirty bounded queries were then executed against all 300 components.

- Result: PASS for correctness.
- Relevant memory ranked first: `30/30`.
- Retrieval-budget violations: `0`.
- Query latency: P50 `438.958 ms`, P95 `475.953 ms`, max `489.437 ms`.
- Forty updates competed with the same `expectedUpdatedAt`: exactly one succeeded and 39 were rejected as stale.
- Restart recovery preserved the query result, 301 Policy events, and the prior-revision recovery archive.
- The packaged CLI accepted the `memory_lab_query` schema and returned the expected Agent-runtime routing contract. Direct CLI tool mode does not execute runtime-routed Memory Lab queries.

### Sustained-query finding

The 300-component, 600-query run did not complete within the 180-second command budget and remained inside the query phase after another 25-second observation window. At that point it had consumed approximately `93.09` CPU seconds and had not emitted the first update Policy event.

This is a real performance finding, not a correctness failure: every query maps over the complete component index and synchronously rereads every component core file before scoring. The bounded output budget limits prompt injection but does not currently limit filesystem scan cost. A future performance fix should cache indexed/scored component text with revision-aware invalidation or add a bounded candidate prefilter before content reads.

## Test-harness corrections

Early probes were excluded from product conclusions until the harness:

- selected the temporary workspace and applied the returned backend snapshot to renderer state;
- read `MemoryLabWriteResult.slug` and `MemoryLabReadResult.component.meta` from their correct locations;
- used the public `max_chars` tool argument;
- cleared completed CDP timeout timers so the harness itself did not hold Node open.

After these corrections, the packaged conversation results above were reproduced without rejection.
