# dev-0.1.7 Desktop Stability and Local Installation

Date: 2026-07-25

## Scope

- Repair Start menu and desktop-shortcut launches that exited without a window.
- Prevent config refresh from freezing the renderer or making the next launch unusable.
- Improve consumer-facing startup recovery and show live changed-file totals in a running Build.
- Rebuild and reinstall the Windows package without changing mutable state under `~/.Newmark`.

## Root Causes

1. The installed `C:\Program Files\Newmark Agent\resources\app.asar` was missing. Electron exited with code 1 before Newmark startup logging could run.
2. Two user-level Start menu shortcuts still targeted removed temporary installations, so Windows search could launch a nonexistent path instead of the machine-wide installation.
3. Config refresh used `window.location.reload()` while the renderer URL still contained the one-shot `startupPrewarm=1` query. The refreshed renderer waited for a startup handshake that no longer existed and left the startup cover active.
4. Config reload waited without a deadline for every runtime pool to stop. An unresponsive child could keep the IPC request pending indefinitely.
5. A second-instance notification only focused an existing window and had no recovery path for a crashed renderer or a lock holder without a usable window.

## Changes

- Remove the one-shot startup query immediately after the main-process readiness acknowledgement.
- Bound config-refresh runtime cleanup to six seconds and return a visible error instead of hanging.
- Reload a crashed renderer and route second-instance recovery through the existing single window-creation path.
- Add a compact running-Build badge with unique changed-file count and added/deleted line totals.
- Extend the packaged startup smoke to call config refresh, reload the renderer, and prove that the startup barrier does not return.
- Remove stale user-level Start menu shortcuts and create one desktop shortcut targeting the machine-wide executable.
