# dev-0.5.9 incremental mobile write tools

## Audit

Full-payload pressure existed in settings provider catalogs, Memory Lab component updates, and text-file writes. Task operations were already item-scoped. Calendar and alarm tools launch one system intent. Memory reindex rebuilds locally and does not require model-supplied bulk data.

## Changes

- Settings: provider/model upsert and confirmed delete, plus partial active selection. Omitted secrets, models, capabilities and tier maps are preserved. Legacy providers-array replacement remains compatible.
- Memory Lab: existing components are selected by component slug/name and patched with only changed metadata. Content supports full replacement, append, or unique old_text/new_text replacement. expected_updated_at, revision archive, policy log and rebuild receipt remain mandatory boundaries.
- Files: private write_file and shared files_manage support overwrite, append and replace. Ambiguous replacements are rejected unless replace_all=true. expected_sha256 rejects stale writes; read_file and shared stat expose SHA-256.
