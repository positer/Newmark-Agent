# dev-0.1.12 Memory Lab one-shot visualization and release

Date: 2026-07-28
Version: `dev-0.1.12`
Repository: `positer/Newmark-Agent`

## Objective

Remove Memory Lab's sustained retrieval bottleneck and make visualization retrieval lifecycle-bound:

- load the complete relationship/content snapshot once on visualization open;
- reload it once on Reset;
- reload it once after reindex succeeds;
- never retrieve relationships or component content because of click, Detail navigation, search, drag, or zoom;
- prevent overlapping render pipelines and repeated node/edge reconstruction;
- retain the earlier low-latency parallel conversation creation/archive changes;
- prove the result in disposable roots before publication.

## Implementation

### Retrieval and consistency

- `memoryLab:visualization` returns the normalized index, all indexed component core Markdown, a stable relationship version, and `loadedAt`.
- Renderer state keeps the snapshot, relationship version, generation token, and load count.
- Only `open`, `reset`, and `reindex` call the visualization loader. A generation token rejects stale asynchronous results.
- Detail and overview component clicks resolve from the snapshot and preserve the current panel/stage.
- `MemoryLab` caches the normalized index and version-keyed component content under a 32-million-character budget.
- Repeated queries use cached index/content. Explicit reads and visualization refreshes force one disk read so external edits are visible.
- Update, delete, and reindex paths update, invalidate, or prune cache entries.

### Rendering

- One running-frame mutex and dirty flag coalesce pending work into a single animation frame.
- Physics and paint are separate functions.
- Repulsion samples a rotating maximum of 24 peers per node instead of all node pairs.
- SVG edge paths and node elements are retained; frames update coordinates and classes without `innerHTML`.
- Strict stage containment and one compositor transform isolate drag paint from layout.
