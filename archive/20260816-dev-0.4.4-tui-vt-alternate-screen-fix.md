# dev-0.4.4 TUI 备用屏 VT 启用修复（光标追踪最终根因，2026-08-16）

## 背景

用户实机测试安装版 `Newmark --TUI` 后报告：滚轮仍能滚动回旧帧、模型长菜单光标追踪仍"离开屏幕"。前两轮（居中滚动、严格窗口约束、备用屏 `?1049h`）都未根治。

## 根因

安装版 `Newmark --TUI` 的真实入口链路不是纯 Node：

```
Newmark.exe (console wrapper, 透传句柄)
  → Newmark Console Runtime.exe (Electron, GUI exe 改 console subsystem)
    → main.ts 检测 isConsoleLauncher → spawnSync 一个 sidecar
      (ELECTRON_RUN_AS_NODE=1 跑 launcher.js, stdio inherit, NEWMARK_FORCE_TTY=1)
        → launcher.js → require('./tui/src/app').start()
```

纯 Node 的 libuv 在 TTY 下会**自动给输出句柄启用 ENABLE_VIRTUAL_TERMINAL_PROCESSING(0x4)**，所以源码/`node bin/newmark-tui.js` 的 pty 测试里 `?1049h` 能生效；但 **Electron-as-node sidecar 不会**做这件事，而 main.ts 里既有的 `setWindowsConsoleMode()` 用错了句柄（`GetStdHandle(-10)` 是**输入**句柄，只设了 `ENABLE_VIRTUAL_TERMINAL_INPUT=0x200`），且只在与 sidecar 无关的路径执行。结果：输出句柄 VT 处理未启用 → `?1049h` 字节虽发出，但 ConHost/传统控制台**不解析** → 备用屏不进入 → 主屏保留滚动历史 → 滚轮能滚回旧帧、2J 重绘随终端滚动错位（"光标离开屏幕"）。

## 修复

1. `DESKTOP/src/main.ts` `setWindowsConsoleMode()`：
   - 输出句柄 `GetStdHandle(-11)` 设 `mode | 0x4`（ENABLE_VIRTUAL_TERMINAL_PROCESSING）。
   - 输入句柄 `GetStdHandle(-10)` 设 `(mode & ~0x7) | 0x200`（原始输入 + VT 输入）。
   - 返回输出句柄原始 mode 供退出恢复。
   - 在 `spawnSync` sidecar **之前**调用（console mode 是 per-console 共享，sidecar 继承）。
2. `TUI/src/app.js` 新增 `enableWindowsVirtualTerminal()`：Windows 下对输出句柄设 VT、输入句柄设原始输入，作为 main.ts 之外入口（`node launcher.js --TUI`、开发模式）的保险；仅在 `NEWMARK_FORCE_TTY=1` 或 `!process.stdout.isTTY` 时调用（纯 Node libuv 已启用的路径跳过，避免多余 spawnSync）。
3. `DESKTOP/src/tests/verify.ts` 新增 3 条回归断言（输出句柄 `-11` + `0x4`、sidecar 前调用、app.js 保险）。
