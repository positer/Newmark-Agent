# dev-0.2.3: conversation-bound drafts, scroll anchoring, Ultra tier, balance-safe provider failures (2026-08-02)

## Scope

The dev-0.2.3 source advances the four user-visible changes from the release notes, plus the provider-balance
hardening discovered while testing the subagent path:

1. **Conversation-bound input drafts.** The renderer keeps an unsent draft per Conversation target
   (`state.conversationDrafts`, keyed by the active target). Switching Conversations saves the current draft,
   restores the draft of the newly selected Conversation, and a successful send clears the stored draft.
   Drafts never leak across Conversations and survive switch-and-return.

2. **Live transcript scroll anchoring.** Before a destructive rerender the renderer records whether the view was
   anchored at the bottom (`chatWasAtBottom`); after rendering it reapplies the previous `scrollTop` and only
   follows the bottom when the view was already there. Reading older history is no longer interrupted by
   auto-scroll, while a bottom-anchored view keeps following live updates.

3. **Ultra orchestrator tier.** A real sixth intelligence tier in `models.default_intelligence`. The provider
   boundary receives `max` reasoning effort; the primary Agent prompt additionally instructs it to act as an
   orchestrator that dispatches specialized SubAgents and coordinates the team.

4. **Safe provider-balance failures.** 402/insufficient-balance responses are classified as
   `balance_exhausted` by the router and detected in the provider result path (kernel streaming catch in
   `agentKernelRunner.ts` and the `process()` provider-result catch). The cooldown is recorded per
   deployment (`providerBalanceBlockedUntilByDeployment`, keyed by providerId+modelId): a failed deployment is
   paused for 5 minutes with a clear `Provider balance exhausted (HTTP 402) for providerId/modelId` error,
   while every other provider stays usable — switching provider or model resumes immediately, and Auto routing
   excludes cooldown-locked deployments from its candidate list. A 402 is never streamed as Agent prose.
   This also explains and fixes the reviewer-subagent error seen earlier in testing (the same 402 surfacing
   through the subagent path; the peer marks only its own deployment). Tool provisioning keeps its broker
   available with no preloaded schema.

## Key implementation points

- `DESKTOP/src/core/autoRouter.ts` — `RouteFailureType` union gains `'balance_exhausted'`; 402 classification.
- `DESKTOP/src/core/agent.ts` — per-deployment balance cooldown `providerBalanceBlockedUntilByDeployment`
  (keyed by providerId+modelId); `process()` entry guard rejects only the failed deployment and clears a stale
  blocked deployment for Auto re-routing; provider-result catch arms the cooldown for the active deployment;
  `autoRouteCandidates()` filters out cooldown-locked deployments; Ultra tier mapping and orchestrator prompt;
  subagent 402 handling (the peer marks only its own deployment).
- `DESKTOP/src/core/agentKernelRunner.ts` — provider stream catch marks the balance cooldown for the deployment
  in use, so 402s surface as errors with the cooldown armed at the exact failure point.
- `DESKTOP/src/ui/index.html` — `state.conversationDrafts` save/restore/clear around Conversation switches;
  `chatWasAtBottom` + `shouldAutoScroll`/`autoScrollIfAtBottom` for scroll-preserving rerenders;
  Ultra entry in the intelligence selector.
- `DESKTOP/src/tests/guideUiReconcileVerify.ts`, `workspaceMenuVerify.ts` — fixture stubs matching the new
  rerender contract.
- `DESKTOP/scripts/dev023-balance-stress.cjs` — repeatable 402 balance-block stress gate.
