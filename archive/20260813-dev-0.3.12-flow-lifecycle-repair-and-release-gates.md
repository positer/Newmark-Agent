# Newmark Agent dev-0.3.12 Flow lifecycle repair and release gates

Date: 2026-08-13

## Scope

Repair the user-visible paused-Flow continuation failure, protect the app's background/close lifecycle, and make archive a non-blocking destructive interruption even while a Flow is running. Validation stayed in disposable roots and the rebuilt `release/win-unpacked` package. No global UAC installation was performed and no Program Files process was terminated.

## Root causes

1. `DESKTOP/src/core/flow-runner.ts` intentionally rejected any `running` WorkRun. After an explicit Flow interruption, the isolated resume Agent could reload the interrupted ledger before the previous owner had flushed its terminal state, so resume incorrectly reported `Flow component #0 cannot start before the previous Build block has terminated`.
2. Flow state was owned by `activeFlowsByRuntimeKey`, but archive only stopped the utility/WSL runtime. The Flow owner and its late `catch/finally` path could therefore keep running or recreate a suspension after archive.
3. `saveStoredFlowSuspension` used a merged state write whose disk snapshot could reintroduce a key that had just been cleared. This made a deleted suspension look resumable after archive or new work.
4. The renderer removed the row optimistically but did not remove the target Flow takeover at click time, so a late Flow event could leave a visible takeover over the replacement conversation.

## Repairs

- Added target-scoped `interruptRunningConversationWorkRuns()` for explicit paused-resume and archive boundaries; genuine concurrent Build protection remains in `flow-runner.ts`.
- Reconciled the paused target before `flow:resume`; a resumed Stop/Esc now returns to the interrupted suspension path instead of becoming a terminal IPC failure.
- Added `archiveRequested` and `interruptActiveFlowForArchive()`; archive marks the Flow before aborting, aborts the provider/kernel, force-finalizes target WorkRuns, clears suspension state, removes the active Flow map entry, and prevents late callbacks from persisting or displaying state.
- Archive now starts target runtime force-stop in the background and single-flights duplicate archive requests; archive payload persistence remains asynchronous/atomic.
- Reworked Flow suspension persistence to mutate the latest locked state directly and explicitly delete both scoped and legacy suspension keys.
- Removed the target row and Flow takeover immediately in `archiveConv`; failed receipts show a notice but never roll the destructive UI state back.
- Added startup diagnostics for renderer unresponsive/responsive, window close request, hide-to-tray, exit close, and `will-quit` transitions.
- Added the Flow pressure scenario to `test:desktop:built` so stale running-ledger regressions are part of the built desktop gate.
