# dev-0.5.9 mobile local tool help repair

## Problem

Android local Agent advertised `settings_update` as a required `json` string containing another JSON object. Compatible providers therefore had to generate and escape two JSON layers, and could become stuck correcting tool-format errors. The placeholder `ProviderConfig...` did not independently describe provider/model fields. Capability-bound tools also had terse help such as only “command” or “path”, so Root/Shizuku and non-privileged modes did not receive equally self-contained schemas.

## Root cause

`LocalTools.function()` emitted an open object schema without `additionalProperties`, and descriptions relied on surrounding product knowledge. `settings_update` chose a string envelope instead of native function-call nesting. The execution layer also accepted only low/medium/high although the product exposes six intelligence tiers.

## Fix

- `settings_update` now accepts top-level `providers` and/or `active` with nested ProviderConfig, ModelConfig and ActiveModel schemas.
- `LocalToolExecutor` still accepts the dev-0.5.8 `{"json":"..."}` envelope for active historical conversations.
- Every tool schema is a closed JSON object with explicit properties, required list, field types and standalone call-format help.
- Capability definitions are auditable as normal/Plan and full-capability/Plan sets. Shared-file, app-list, Root, Shizuku and ADB tools state authorization boundaries, side effects and output semantics.
- settings execution uses all six intelligence tiers: low, medium, high, xhigh, max and ultra.
