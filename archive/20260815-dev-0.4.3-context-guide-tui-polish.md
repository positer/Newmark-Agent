# dev-0.4.3 任务清单同步 + TUI 光标跟随 + 上下文窗口统计 + Guide 注入优化（2026-08-15）

## 背景 / 目标

在 dev-0.4.2 之上完成 dev-0.4.3 任务清单：

1. 动态 task-list 注入改为软性固定提示（缓存友好）+ task-read/task-create 工具读写 conversationPlan。
2. TUI 长列表光标跟随修复（flowtask/palette/flow-select/chat 列表）。
3. GUI 上下文用量 128000 上限 → 按模型实际上限。
4. 删除「借鉴 DSH 动态管理」等借鉴声明文案。
5. 上下文管理窗口去关闭按钮、点外自动关闭。
6. 上下文用量窗口统计全对话 token + 缓存命中率。
7. conversation_rename 首轮响应总结命名。
8. Build Block「编辑了文件」默认折叠。
9. Guide 注入优化：连续 Guide 合并续接；Build 内顺序自动接续、跨 Build 最新优先不自动接续；意外中断 Build 的历史主动接续并共用上下文缓存。
10. 确保上下文机制在 Build block 内完成几乎全量上下文命中。

## 发现与决策

- 任务清单动态注入确实存在：`buildRequestTaskFocus` 会把 `conversationPlan.items` 逐项写进 provider system 段，条目标题/状态每轮变化会反复破坏前缀缓存。改为固定软性提示，具体清单通过 `task_read` 读取、`task_create` 写入。
- TUI 长列表问题分四处：`flowTaskView` 的 `contentFocusLine = 6 + index * 2` 在非 logic 组件时行号错位；palette/flow-select 覆盖层固定 `slice(0,7)` 或全量渲染，无滚动窗口；chat 左侧会话列表无滚动窗口。分别改为真实行号 / 独立 scroll 状态。
- 上下文窗口已按模型 `max_tokens` 解析（`resolveWindowModel`），但缺少全对话 token 与缓存命中率统计。新增 `Agent.providerUsageTotals/lastProviderUsage` 与 `recordProviderUsage`，由 kernel 的 usage token 路径累积，UI 展示累计 input/output 与 `cacheRead/input` 命中率。
- Guide 连续注入原实现每来一个 pending Guide 就 `runSingle` 一次，每个 Guide 单独触发一次 provider 响应。改为在 conversation kernel 的 pending 队列中合并连续 receipt-tracked steer 为 `batchGuides`，单条 Guide 保持原路径不变（避免破坏既有 deferred/end-of-block 生命周期）。
- `conversation_rename` 原实现是首 Build bootstrap 注入一次性 tool-call 指令；改为在首个完成 Build 的最终响应处由 `deriveConversationTitleFromSummary` 派生标题并自动 rename，减少首轮 tool-call 且更贴合实际工作内容。
