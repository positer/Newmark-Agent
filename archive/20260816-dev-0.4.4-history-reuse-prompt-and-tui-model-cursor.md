# dev-0.4.4 历史 Build 信息主动复用 prompt + TUI 模型长菜单光标跟随加固（2026-08-16）

## 背景 / 目标

1. **prompt 优化**：让非首轮 build block 在任务延续/修复/验证/依赖历史工作时，**主动调用 build_history_query 读取历史 build block 的具体操作信息**（工具调用/结果/文件改动），复用已有信息，而不是每一轮都重新调查（重新跑命令/重新读文件）。
2. **TUI 光标追踪**：用户报告 dev-0.4.3 后"模型选择长菜单仍然离开屏幕"。

## 发现与决策

### 任务 1：历史信息复用 prompt（被动 → 主动）

现状是「被动」语义：`buildConversationTaskLedger` 末尾只写 "When concrete work details are required, call build_history_query..."（仅当用户问细节时才查询）；`CORE_SYSTEM_PROMPT` 的 disclosure 写 "Use build_history_query only when the current user asks what specifically happened"；工具描述同为 "call this read-only tool only when the user asks what specifically happened"。模型在开启新 Build 时会重新调查而不是先看历史块已做过什么。

改为「主动复用」语义（保留只读/不授权恢复的安全边界）：
- **ledger**（agentKernelRunner.ts）：当本次任务延续/修复/验证/依赖列表中的历史工作时，**在重新调查之前**先 `build_history_query`（history_index 来自 ledger），复用返回的工具活动与结果，而不是重新运行命令或重新读取本对话已检查过的文件。
- **disclosure**（agent.ts）：同样改为「任务延续/修复/验证/依赖历史 Build Block 时主动调用」。
- **工具描述**（tools/index.ts build_history_query）：改为 "Call it proactively when the current task continues, fixes, verifies, or depends on earlier work: reuse the returned activity instead of re-investigating from scratch"。

缓存约束核验：三处均为**静态文本**；ledger 属于每 Build 首请求注入的 bootstrap（Build 内稳定，工具子轮不复述），disclosure 属于 stable system prompt，工具描述属于 tools schema（identity 不含描述文本）。`contextCacheHitStressVerify` 29/29 确认前缀缓存不破坏。

### 任务 2：TUI 模型长菜单光标跟随

**排查过程**（未直接复现"高亮不可见"）：
- 进程内模拟：model 视图 Deployment 列在 60/300 模型 × 100x24 / 100x18 / 70x24 compact / 52x20 全组合逐步/随机跳变，高亮始终在视口内。
- 真实 pty（node-pty + 临时 root + 60/40 模型配置 + 用户真实配置副本 30 模型）：`--root` 真实 runtime 下 model 视图滚动跟随正常，高亮可见。
- 打包 asar 内 `dist/tui/src/render.js` 与源码哈希一致（含 dev-0.4.3 全部滚动修复）。
- 排查发现 dev-0.4.3 的 cursor-follow 压力测试**漏掉了 model 视图**（只覆盖 chat/palette/flow-select/flowtask）。

**发现两个真实缺陷并加固**：
1. **选中行贴底/描述行被裁**：内容视图滚动算法是「贴边修正」（焦点越界才滚动到刚好可见），两行一组的模型选项（主行+描述行）滚动到底部时主行贴在视口最后一行、描述行被滚出视口——用户感知为"光标离开屏幕"。改为**居中跟随**：焦点行尽量保持在视口上 1/3 处（`targetLine = floor(bodyHeight/3)`），上下都留内容，主行+描述行同时可见。实测高亮从 row 26（贴底）移到 row 17（视口中上部）。
2. **modelView 硬编码行号**：`contentFocusLine = 14 + index * 2` / `5 + index` 依赖 INTELLIGENCE_TIERS 恰好 6 档的前缀布局，档位数变化即错位。改为**动态行号**（`tierStart`/`deploymentStart = rows.length` 记录真实起始行）。

**用户复报后追加修复（严格窗口约束 + 实时尺寸自适应）**：
3. **窗口尺寸强制放大是根因**：`render()` 原来 `Math.max(52, columns)` / `Math.max(20, rows)` 会把帧强制放大到最小 52x20——当终端窗口小于该尺寸（如 40x12、60x16）时，**帧画到窗口之外**，底部行/右侧列（含模型长菜单的高亮行）落在窗口外用户看不到。修复：宽度/高度直接采用终端实际尺寸（不再放大），输出阶段每行按可见宽度 `truncate` 到窗口宽度、行数限制在窗口高度内（`boundedBody`/`boundedFooter`），覆盖层行也截断——**帧绝不越界**。
4. **实时尺寸读取**：新增 `readWindowSize()`，每次渲染优先 `process.stdout.getWindowSize()`（实时查询底层 TTY，不依赖 Node 缓存），回退缓存 `columns/rows`，再回退 `COLUMNS/LINES` 与默认值；`render()` 无显式参数时每次实时读取，配合既有 `resize` 监听，窗口拖动后即使 resize 事件延迟，下一次按键/动画重绘也用新尺寸。
5. **无功能 TUI 打包前门禁**：`data.js` 支持 `NEWMARK_TUI_DEMO_MODELS` 环境变量注入长模型列表（--demo 纯渲染模式）；新增 `TUI/test/cursor-follow-pty-gate.js`（node-pty 拉起无功能 demo TUI）——三窗口组合（100x24 / 40x12 / 60x16）遍历模型长菜单断言高亮在屏、主行+描述行同屏、帧行数=窗口高度、每行宽 ≤ 窗口宽；**真实 resize 自适应**场景（100x24 → 40x12 → 90x28 → 52x15 动态缩放后继续遍历，断言每帧严格 ≤ 实时窗口）；挂入 `test:tui:built` 打包门禁。demo.test.js 新增小窗口严格约束断言（20x8/30x10/40x12/60x16 全模型遍历）+ readWindowSize 实时读取单测（getWindowSize 优先 / COLUMNS·LINES 回退 / render 无参按实时尺寸绘制）。清理 TUI/test 历史遗留 tmp 调试文件，`node --test` 全量可跑。

**用户再次复报后确认的真正根因（alternate screen buffer 缺失）**：
6. **TUI 从未进入备用屏幕缓冲（alternate screen）**：一直在主屏上画，主屏保留滚动历史——用户能用鼠标滚轮滚回上一次刷新（旧帧），任何终端滚动都会让 `2J` 全量重绘错位，表现为"光标（高亮）离开屏幕"。修复：启动输出 `\u001b[?1049h` 进入备用屏（无滚动历史，滚轮无效、终端不滚动），每次刷新仍在备用屏内 `?25l 2J H` 全量重绘；退出 `\u001b[?25h\u001b[?1049l\u001b[0m\u001b[2J\u001b[H` 恢复主屏与光标（含 `process.on("exit")` 兜底）；`paint.cancel()` 丢弃退出前排队的重绘，避免恢复主屏后又被画上一帧。
7. **退出序列丢失修复**：退出序列与关闭消息改为 `fs.writeSync(process.stdout.fd, ...)` 同步写——此前 `process.stdout.write()` 异步写 + `process.exit()` 会在字节到达 pty 前被丢弃（探测确认 write 回调已触发但 ConPTY 未收到消息）。
8. **pty 门禁重构为普通脚本**：`cursor-follow-pty.test.js` → `cursor-follow-pty-gate.js`（非 node:test），因 Windows 上 node-pty 的 ConPTY 辅助进程残留句柄会让 node --test runner 永不退出；脚本 main() 末尾显式 `process.exit(0/1)` 确定性结束。
