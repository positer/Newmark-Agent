# dev-0.4.3 模型思考强度档位映射（thinking_tier_map）

日期：2026-08-16
版本：0.4.3（source PASS，未打包 / 未发布）

## 背景与目标

不同模型的原生思考强度档位（reasoning effort）配置可能不同：档位数量不同（如只支持
low/medium/high 三档）或档位命名不同（如 minimal/balanced/deep）。此前 `LLMProvider`
一律把 Newmark 档位名（low/medium/high/xhigh/max/ultra）原样作为 `reasoning_effort`
透传，遇到档位体系不同的模型会发送模型不认识的档位名。

本次在模型配置中新增可选 `thinking_tier_map`：把模型原生档位映射到 Newmark 五档位
（`low/medium/high/xhigh/max`），请求时按映射把 Newmark 档位反查为模型原生档位名。
未配置映射时保持默认不变动（默认跟随既有行为）。

## 设计

### 配置层（`DESKTOP/src/core/config.ts`）

`ModelConfig` 新增可选字段：

```ts
thinking_tier_map?: Record<string, string>;
// 键 = 模型原生档位名；值 = Newmark 五档位之一（low/medium/high/xhigh/max）
```

`defaultModelConfig` 不设置该字段（undefined = 未配置 = 默认不变动映射）。
`config.example.json` 模型条目新增示例（minimal/balanced/deep → low/medium/high）。

### Provider 层（`DESKTOP/src/llm/provider.ts`）

- 构造新增第 8 可选参数 `thinkingTierMaps?: Record<string, Record<string, string>>`
  （模型名 → 该模型的映射表）。
- `reasoningEffort(model, tier)` 先经新私有方法 `mappedNativeEffort(model, tier)`：
  1. 无映射 / 映射为空 → 返回 undefined，走既有默认逻辑（默认不变动映射）；
  2. 精确命中：映射中 value === Newmark 档位（ultra 归一为 max）的 key；
  3. 就近降级：取强度不超过目标档位的最高已映射档位对应的 key；
  4. 全部高于目标档位：取最低档位对应的 key；
  5. 非法 value（不在五档内）被过滤。
- v2 adapter 修复：`chatStreamWithToolsV2` 的 chat_completions 请求此前漏带
  `reasoningEffort`（responses 桥 `adapterResponsesBridge` 一直携带），本次补上，
  与 legacy `chat()` 路径（`applyChatReasoningEffort`）行为对齐。

### Adapter 契约（`DESKTOP/src/providers/provider-adapter.ts`）

`NormalizedAgentRequest.reasoningEffort` 由 `'low'|'medium'|'high'|'xhigh'|'max'`
放宽为 `string`：映射后的原生档位名可能是任意字符串，adapter 只负责透传。

### Agent 层（`DESKTOP/src/core/agent.ts`）

新增私有助手 `modelThinkingTierMaps(model)`，把模型配置的 `thinking_tier_map` 包装成
`{ [model.name]: map }`；`engineModel` / 模型校验循环 / editor 请求 / subagent
assigned provider 四处构造 `LLMProvider` 时均传入。

### GUI（`DESKTOP/src/ui/index.html`）

- 新增/编辑模型弹窗新增「思考强度档位映射」文本域：每行 `原生档位=Newmark档位`
  （如 `minimal=low`），留空表示不变动映射；帮助文案沿用 fuzzy 弹窗的
  `margin-top:10px;font-size:11px;color:var(--text-dim)` 风格。
- 助手：`parseThinkingTierMap(text)` / `serializeThinkingTierMap(map)`。
- 模型列表 chip 在配置了映射时显示「Thinking tier map N」摘要。
- i18n：en/zh 新增 `model.thinkingTierMap` / `model.thinkingTierMapHelp`。

## 影响面

- 未配置 `thinking_tier_map` 的模型：请求体与 dev-0.4.3 之前字节级一致
  （除 v2 chat_completions 现在会携带 `reasoning_effort`——这是修复漏传，
  与 legacy 路径对齐；对 gpt-5/o1/o3/codex/reasoner/r1 等模型产生新增字段，
  属于预期修复）。
- 配置了映射的模型：发送模型原生档位名，不再发送 Newmark 档位名。
