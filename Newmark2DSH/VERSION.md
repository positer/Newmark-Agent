# Newmark2DSH version ledger

Every release records one line here, and the release gate refuses a version this file does not
account for. The numbering is not standard semver: the three fields are
`0.<sub-components added>.<everything else>`, and **neither position carries at ten** — so
`0.1.9` is followed by `0.1.10`, `0.9.0` by `0.10.0`, and `0.12.13` is a legal version. The rule
and its reasoning are in `taste.md`, "Newmark2DSH 版本号约束（严格）".

The reason for that shape: `minor` records addition releases of this package. As explicitly
requested for 0.3.0, multiple sub-components introduced together advance this field only once; `patch` counts every other
change. Letting them carry would turn two counters into one overflowing semantic digit.

## Kinds

- **sub-component** — a sub-component was added to the bundle. `minor` + 1, `patch` → 0.
- **sub-component change** — a change inside an existing sub-component. `patch` + 1.
- **core** — the plugin core: the core row, composition, the control route, the client panel,
  packaging, or the bundle's own patch. `patch` + 1.
