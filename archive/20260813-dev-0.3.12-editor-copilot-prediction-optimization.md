# dev-0.3.12 built-in editor Copilot prediction optimization — 2026-08-13

## User symptom

The native editor frequently displayed `No completion`, prediction requests felt very slow, and rapid caret movement could leave an older request competing with the current editor state.

## Root causes confirmed

- Every caret/input change invalidated the previous renderer request, but the provider request was not cancelled immediately.
- Completion used the normal non-streaming provider path and inherited the global OpenAI API mode (`chat` in the local user configuration).
- Each request sent up to 6,000 characters before and 1,600 characters after the cursor and allowed 192 output tokens.
- Any enabled GitHub Models record could win model selection before a valid active deployment, even when its credentials or validation state were unusable.
- Empty, whitespace-only, aborted, and superseded results were rendered as a visible `No completion` popup.
- Caret movement re-rendered the full syntax-highlighted editor, adding avoidable main-thread work while typing.

## Changes

- `DESKTOP/src/core/agent.ts`: filters usable deployments, bounds context to 3,200/800, 96 output tokens, 1,200 UI chars, 6.5-second deadline, forces completion `chat_stream` without changing normal chat mode, relays text deltas with bounded chat fallback.
- `DESKTOP/src/main.ts` and `DESKTOP/src/preload.ts`: owner-scoped immediate cancellation and renderer-scoped completion delta IPC.
- `DESKTOP/src/ui/index.html`: 300ms debounce, short-lived anchor cache with content fingerprints, immediate cancellation, streamed ghost deltas, quiet empty/timeout/abort/superseded states, caret-only status/ghost rendering.
- `DESKTOP/src/tests/editorCompletionVerify.ts`: deterministic backend/renderer regressions.
