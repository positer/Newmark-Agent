# dev-0.1.9 Workspace-bound Automation Builds

## Scope

- Require every automation to specify a workspace.
- Let the user choose a fresh conversation per trigger or a specific existing conversation.
- Start a distinct Build block in the configured target when the schedule becomes due.

## Implementation

- Added persisted workspace identity/name, conversation strategy/id, and last-triggered conversation id.
- Creation and update validation reject missing workspaces and missing existing-conversation ids.
- Desktop triggers resolve the stored workspace and use `ConversationKernel.prompt()` with Build mode.
- An active target run is awaited before the scheduled Build starts, preventing scheduled work from being appended to the prior Build block.
- New-conversation schedules allocate a unique conversation id for every run; existing-conversation schedules keep their configured id.
- Automation UI, Agent tool schemas, formatting, IPC creation, and Server fallback carry the target fields.
