The adopted engineering principles are:

- Wrong, stale memory is more dangerous than a missing memory.
- Policy controls the full chain: Pre-Think → Retrieve → Write/no-write → ADD/UPDATE/DELETE.
- Short-term context needs Retrieve/Summary/Filter, not unconditional context injection.
- Retrieval quantity should be adaptive rather than a fixed top-k.
- Mutation decisions must be observable, replayable, and recoverable.

## Gap audit

Newmark already had:

- on-demand Memory Lab tools rather than unconditional system-prompt injection;
- context compression with task-state headings and retained latest instructions;
- request-scoped focus blocks that mark historical summaries as untrusted data;
- a tag DAG and verified rebuild receipts.

The missing production controls were:

- no bounded focused retrieval tool;
- no explicit DELETE action;
- updates directly overwrote core memory without revision archive;
- no optimistic concurrency token for stale writers;
- no append-only mutation decision log;
- no deterministic retrieval explanation or adaptive stop rule.

## Implementation

- Advanced `DESKTOP/package.json` and `package-lock.json` to `0.1.11`.
- Added `memory_lab_query` with deterministic multilingual scoring across name, tags, description, and bounded content.
- Query output is limited to 1–12 hits and 1,000–48,000 characters; component scans are capped at 64,000 characters.
- Retrieval stops after the requested limit, character budget, or when the next score is below 35% of the strongest result.
- Added per-component revision numbers.
- `memory_lab_update` now distinguishes ADD from UPDATE, accepts `expectedUpdatedAt`, archives the prior core Markdown, and appends a Policy event.
- Added `memory_lab_delete`; it rejects stale deletion, archives the final revision, removes active memory, rebuilds the index, and returns `rebuildReceipt.completed=true`.
- `Memory Lab/policy.jsonl` records action, target, reason, source, revision, timestamps, content hash for writes, and recovery archive path without storing memory content.
- `Memory Lab/archive` stores recovery Markdown with metadata headers.
- Plan mode allows bounded query/read but blocks update/delete/reindex.
- Updated Agent policy text and native tool definitions so the model pre-thinks retrieval and only mutates durable memory under user authorization.
- Added a folder-to-file revision migration guard after Windows verification exposed a process-level `fs.cpSync` crash; recovery archives now store canonical core Markdown and type changes remove the old container safely.

## Acceptance target

Newmark should retrieve only bounded task-relevant memory, fail closed on known-stale mutation, preserve every replaced/deleted revision, expose ADD/UPDATE/DELETE as distinct policy actions, and leave a replayable decision trail without injecting all long-term memory into the prompt.
