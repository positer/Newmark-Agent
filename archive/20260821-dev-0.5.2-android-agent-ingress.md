# dev-0.5.2 Android Agent surface and ingress

Date: 2026-08-21 (Asia/Shanghai)

## Scope

- Make local provider latency visible as the PC-style public Build thought activity.
- Advance running WorkRun duration independently from event arrivals.
- Expand the sandboxed terminal to a broad tmux-scale command vocabulary.
- Add a local `calendar_create` Agent tool through the Android calendar UI.
- Receive system text/files and route cold/warm local/remote deliveries precisely.
- Improve address completion and make WebView navigation fail closed.
- Bind desktop and Android to `dev-0.5.2`.

## Design and safety boundaries

The thought event is a lifecycle shell only. Provider text may become its public description, but private reasoning fields are neither requested nor rendered. The timer recomposes only the WorkRun header every 100 ms and freezes against `endedAt`.

Terminal commands are Kotlin implementations over the app-owned workspace rather than an Android system shell. Canonical path validation remains mandatory. Copy/move do not overwrite, removal rejects the root and non-empty directories, output is bounded, and the Agent tool surface remains separate from interactive aliases.

Calendar creation follows Android's documented Calendar Intent flow: `ACTION_INSERT`, `CalendarContract.Events.CONTENT_URI`, documented event extras, and user confirmation in the calendar app. No calendar provider permission was added.

Share ingress accepts `ACTION_SEND` and `ACTION_SEND_MULTIPLE`, but only reads `content://` URIs. Display names are sanitized, declared and observed sizes are capped at 20 MiB, stream reads run on `Dispatchers.IO`, and remote uploads retain their frozen workspace/conversation target. `singleTask` delivery is paired with live `onNewIntent` handling for both share intents and `newmark-pair` deep links.

Browser input resolution and callback validation are distinct. Search fallback is address-bar-only. Callback navigation permits only parsed HTTP(S) URLs with a host and without credentials/control characters/whitespace; WebView keeps file/content access, mixed content, popup windows and geolocation disabled and returns to safety on Safe Browsing hits.
